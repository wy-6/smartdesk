## 从数据里读出来的结论

1. **切片大小必须按文档长度调，不是越大越好。**
   本次评测集的文档普遍在 200~400 字之间。当 chunk-size=800 时，一份制度被整个塞进一个切片，向量把「密码策略 + 漏洞修复 + 数据分级」平均成了同一个方向，查询「密码最少多少位」时就命中不了它 —— **切片太大 = 一个切片里混了多个主题 = 什么都不像**。
2. **重叠有实际价值。** overlap=0 时，答案正好落在切割线上就会整题丢失；overlap=80 让相邻切片共享一段文本，跨界的句子至少有一片是完整的。
3. **Top-K 是召回与噪音的权衡。** K 越大召回越高，但塞进 Prompt 的无关片段也越多，模型越容易带偏。本项目默认 K=5。
4. **检索命中率与引用正确率必须分开看。** 前者是检索问题，后者是生成问题。检索没命中却出现正确引用属于运气；检索命中了但引用指错，说明 Prompt 的引用约束还不够。本项目三种配置的「引用错误数」都是 0 —— 因为引用列表由检索结果生成，模型只能引用真实存在的编号。
5. **本评测用的是离线 mock 嵌入（词元哈希）**，衡量的是词面重叠能力。上面「同义改写召回率」那一节把这个局限量化出来了：换成同义说法后，召回率从 90.0% 掉到 63.3%。换成真实语义嵌入后 hit@1 通常会明显上升（“语义相近但词面不同”的查询也能召回），但**相对**结论（切片别太大、重叠有用、K 别贪多）依然成立。
